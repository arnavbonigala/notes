So,&nbsp; here's the story: We need to organize large&nbsp;&nbsp; programs that are very complex into small, modular&nbsp; components that can individually be written,&nbsp;&nbsp; tested, and thought about all at once. Because&nbsp; humans can only think about so much complexity&nbsp;&nbsp; at a time, we do this with data abstraction. But&nbsp; object-oriented programming takes that idea one&nbsp;&nbsp; step further by bundling together multiple pieces&nbsp; of information, like with data abstraction, and&nbsp;&nbsp; also related behavior. So that an object, which&nbsp; represents something in the world such as a date,&nbsp;&nbsp; not only stores all the information necessary&nbsp; to represent that date but also can perform&nbsp;&nbsp; date-like things, such as determining&nbsp; what day of the week that date falls on. Each object&nbsp; should know how to manage its local state,&nbsp;&nbsp; meaning that it keeps track of what changes are&nbsp; allowed, and the way in which you interact with an&nbsp;&nbsp; object is using what's called a method, which is a&nbsp; function that's particular to that kind of object.&nbsp;&nbsp; Several objects may all be instances of a common&nbsp; class, which is a type of object.
